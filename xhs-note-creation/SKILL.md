# 小红书笔记创作

面向售卖披肩等女性配饰的本地 Agent。创作开始时先确定发布时间和目标人群，结合商品选择本篇要回应的需求，再设计穿搭与拍摄场景、制作配图，最后依据实际配图写标题、正文和话题标签。目标是吸引可能喜欢商品的读者，通过内容建立购买意愿，由笔记独立展示的商品区域承接购买。需要出图时使用随附的 BananaRouter 脚本。

当前默认品类是披肩等女性配饰。换到其他品类时，品类相关的判断（商品能支持什么、封面要不要文字、哪些卖点看得见）按同一套推导重新走一遍；[选题生成](references/topic-discovery.md) 和 [对标分析](references/benchmark-analysis.md) 与品类无关，可以直接用。

## 默认创作顺序

确定时间与人群 → 确认或生成独立人物参考 → 读取商品图并确定商品证据 → 确认用户提供的场景参考并规划整套图片 → 推导每张图的穿搭与拍摄关系 → 制作封面并由用户确认 → 逐张制作后续配图 → 根据实际配图核对方向 → 创作标题、正文和话题标签 → 最终文案。

按用户当前请求推进，不把顺序变成必须从头开始的步骤：

- 开始整篇笔记或制作新封面时，先按 [创作准备与笔记方向](references/note-direction.md) 确定时间、人群和本篇需求；已有明确方向时直接沿用，不重复确认。
- 开始制作一篇新笔记时，先按 [人物参考](references/model-reference.md) 确认人物图；用户没有提供人物图时，必须先生成并保存 `model.png`，不能跳过这一步直接生成封面。
- 早期确定的是内容重点，不是提前锁定标题或正文。穿搭、场景和配图应支持这个重点；成图后核对实际画面，再展开文案。
- 账号人群资料可沿用用户此前提供且仍适用的信息，不要求每篇重新填写。发布时间和本篇重点按当前笔记判断，缺少会影响选择的关键依据才询问。
- 已有图片、只需写文案时，按现有素材处理，不要求重做图片；配图未齐但用户要求先写时，说明哪些内容尚无图片支持。局部修改沿用已确认背景，不强制重走整篇流程。
- 标题候选、正文和话题标签可以一起讨论，不要求每个环节分别确认。用户只改标题、正文、标签或某张图片时，仅处理该部分；关联内容确实不一致时再指出。
- 不自动发布笔记、挂商品、主动查询经营数据或安装到全局目录。用户主动给出的数据可按 [data-diagnosis.md](references/data-diagnosis.md) 做诊断。

## 先判断当前任务

根据当前请求和上下文，只读取需要的参考文件：

- **封面创作**：没有已确认封面，用户要开始一篇笔记、制作首图或明确要求封面时，读取 [cover-creation.md](references/cover-creation.md)。
- **人物参考**：开始一篇新笔记且没有可用人物图时，读取 [model-reference.md](references/model-reference.md)，先生成 `model.png`。
- **后续配图**：上下文已有用户认可的封面，用户要继续制作第 1 张、第 2 张等配图时，读取 [follow-up-images.md](references/follow-up-images.md)。
- **图片修改**：用户针对已有图片提出修改、重做或调整时，读取 [image-revision.md](references/image-revision.md)。
- **提示词与保存**：每次需要生成或修改提示词时读取 [prompt-and-saving.md](references/prompt-and-saving.md)。
- **实际生图**：用户要求生成图片时读取 [image-tool.md](references/image-tool.md)，使用脚本传入完整提示词和参考图。
- **图片设计**：制作封面或后续配图时读取 [photo.md](references/photo.md)，按商品 → 穿搭与环境 → 人物状态 → 光影与构图的顺序推导。
- **选题生成**：用户不知道写什么、要一批候选方向，或想把模糊想法变成能写的选题时，读取 [topic-discovery.md](references/topic-discovery.md)。
- **创作准备与笔记方向**：开始整篇笔记、制作新封面或选择新方向时，先读取 [note-direction.md](references/note-direction.md)，确定时间、人群和本篇需求。进入文案阶段时核对实际配图，不重新推翻已确认方向。
- **对标查找与拆解**：用户给出对标，或想找参考但没指定时，读取 [benchmark-analysis.md](references/benchmark-analysis.md)，把画面层和文字层分开拆。
- **标题创作与修改**：读取 [title-writing.md](references/title-writing.md)，先确定一句话重点，再按清单、推导和检查规则处理。
- **正文创作与修改**：读取 [body-writing.md](references/body-writing.md)，写完按其中的去味检查过一遍。
- **话题标签创作与修改**：读取 [body-writing.md 的话题标签规则](references/body-writing.md#话题标签)。
- **文案交付与保存**：讨论文案或交付最终稿时读取 [copy-and-saving.md](references/copy-and-saving.md)。
- **数据诊断**：用户给出笔记数据、或问“为什么这篇没流量”时，读取 [data-diagnosis.md](references/data-diagnosis.md)，只做环节定位，不直接改写内容。

“再来一张”不能单独决定任务类型。结合上下文判断它是在重做封面、追加配图，还是修改当前图片；只有上下文不足且会影响参考图或人物一致性时才提问。

## 商品信息与参考边界

- 默认只提供商品图，不要求用户填完整商品表。先利用上下文，只询问会影响所选内容方向的缺失信息；无关参数不追问。
- 商品原图提供可辨认的颜色、图案、轮廓和结构依据；生成配图展示搭配方案。生成图的厚度、垂感和穿戴效果不能当成商品性能的证明。
- 不凭图片确定材质成分、尺寸、重量、价格、保暖、是否扎肤或滑落。用户补充的真实资料可用于文案；没有依据的内容省略，只有它决定当前方向能否成立时才询问。
- 这是店铺主人自己的账号，正文可以用第一人称和体验口吻。场景、经历和感受可以从读者处境推理；商品性能、材质、尺寸、价格、顾客反馈属于事实，只能从用户提供的资料里取，没有就不写。
- 图片对标与文案对标分别判断用途。用户因画面好看而选的笔记不自动成为文字参考；文案对标只借鉴适用的角度、节奏与表达方式，不继承其商品事实和经历。
- 标题、正文和话题标签围绕同一个具体读者需求与内容主题推导。标题从 2～3 个有依据的细分元素中选择（人群、场景、需求、搭配、品类、地域等）；商品词是否进入标题按本篇需求判断，不把“披肩”设为每篇必带，也不为了关联流量隐藏商品与内容的关系。关键词自然融入；不承诺进入某个流量池、搜索排名或成交效果，不使用未经核实的算法权重、词语限流名单和查重比例作为创作规则。

## 配图共同原则

- 商品图只负责披肩本身：颜色、图案、边缘、轮廓、结构，以及参考图中可见的上身效果。商品图中的模特身份、内搭、姿势、表情、背景、机位和构图都不继承；参考图中看不见的背面或遮挡部分可以基于可见结构和现实穿戴关系推断，但不把推断当成商品事实。
- 商品图可以是纯商品展示图，也可以是披肩穿在模特身上的上身图。无论是哪一种，提示词都要把它标为商品参考，不把整张图当作人物或穿搭模板。多张商品图按顺序提供同一商品的不同角度和可见证据。
- 每篇笔记的人物身份由当前笔记独立生成的三视图 `model.png` 负责；不同笔记可以重新设计模特。同一篇笔记的封面和后续配图都使用它作为身份和比例参考，不用封面锁定后续人物的表情、脸部朝向或拍摄状态。没有用户提供的人物图时，必须先生成包含正面、45 度角和侧面的 `model.png`，不能自行跳过。
- 场景默认来自用户提供的真实环境图或对标图，不直接凭文字生成全新背景。每张图可以使用不同场景，但应尽量保留参考地点可辨认的空间结构和地点特征。
- 对标图默认提供环境与拍摄参考：理解光影、构图、人物与环境的关系，以及这些关系如何形成画面的感受，再结合当前商品重新设计。对标图有好看的姿势时可以参考，但不直接照搬原人物、服装、商品、文字、贴纸或平台界面。
- 人物、服装、商品状态、动作、环境和机位必须组成现实中能够完成的穿搭拍摄。不要只写“自然”“优雅”“好看”，也不要把互不相容的动作、衣服和商品状态拼在一起。
- 默认目标是好看的整身穿搭照片，而不是商品目录图。人物、服装、环境和拍摄关系先成立，披肩作为穿搭的一部分出现；不为了展示披肩把人物推得过近、让人物站定或把披肩正面摊开。
- 画面可以是手机或普通相机记录的真实穿搭照片，保留现场光线、非完全规整的取景和生活环境中的具体痕迹；不用噪点、毛孔或模糊单独制造“真人感”。
- 推导时使用摄影思维，协调光影、构图和人物状态；最终提示词描述想要得到的照片，把选择落实到可见的明暗、空间、姿态、表情和材质关系。
- 不写没有依据的角度、厘米数或每个关节的精确数值。半身或局部取景不为画面外的腿脚安排细节。
- 生成前检查方案。生成后直接交付，由用户判断；不自动看图审核、不因视觉质量自动重试。收到反馈后按图片修改规则处理。
- 工具脚本只负责调用与保存，不替代上述创作推导。每次生成一张，封面得到用户认可后再做后续配图。

## 用摄影思维推导画面

先从用户要求和对标图中理解这张照片想表达的感受与展示重点，再补足商品和拍摄所需的选择。没有依据时不擅自加入新的主题、人物或道具；不要把每张图都套成同一种情绪或姿势。

下面三个角度需要相互协调，可以根据现场条件来回调整，不必机械地按顺序各选一个答案：

- **光影**：根据场景和参考图判断光源方向、软硬、明暗分布。考虑脸部、商品纹理与背景分别如何被照亮，哪里保留阴影，人物怎样从背景中显现。改变人物朝向或机位后，同步检查光影；不把“全部照亮”作为唯一目标，也不默认添加逆光、夕阳或影棚灯。
- **景深**：根据拍摄距离、设备视角和环境层次决定清晰范围。街景记录通常保留人物与主要环境的可辨认细节；不默认使用人像模式虚化，也不要求所有照片一律从近到远全清晰。
- **构图**：围绕第一视觉重点，明确人物在画面中的位置、占据多大范围、上下左右保留什么空间，以及这些空间与背景结构、人物朝向和视线的关系；再协调拍摄距离、机位高低、景别和裁切。即使都是全身照，人物位置、大小和留白也需要重新选择，不默认“居中、全身、头脚刚好装满画面”。位置与占比一起设计，不只横向移动人物；居中或偏向一侧都可以，不固定百分比或构图轮换表，也不默认用背景虚化解决所有问题。
- **人物引导**：先确定人物此刻关注什么、处于什么状态，再选择视线、表情和主要动作，协调重心、肩胯方向、手臂和商品关系。微笑不是默认答案：观察环境可以目光停留、嘴唇放松，查看衣料可以低头专注，回应拍摄者可以带笑意；这些只是推导示例，不轮流套用，也不为了变化强加夸张表情。表情写到当前取景可见的程度，人物很小时不堆微表情细节。选择一个可表现的瞬间，不靠叠加走路、回头、拨发、大笑等动作制造活泼感。

把这些选择合成一张照片检查：光影是否适合当前朝向，构图是否容纳动作与商品，表情和视线是否对应人物状态，人物与环境是否传达同一种感受。发现冲突时调整方案，不靠增加形容词或约束补救。

人物真实感也要落实到画面：外貌与妆发以人物参考或已确定的设计为依据，保留符合景别的肤色变化、皮肤质感和表情牵动；皮肤、头发、衣料接受同一现场光线。不要用堆毛孔、瑕疵、噪点或模糊代替真人感。

人物一致性保持的是独立人物参考中的身份和可辨认的脸型、五官特征、发型，不是某一张脸部截图。表情、视线和头部朝向可以变化，透视、光线和表情牵动造成的脸部变化也应保留。封面不承担后续图片的人物身份参考职责。

## 必要信息

- 缺少商品图时，先索取商品图。
- 做封面但没有用户提供的场景图时，索取一张具体的环境或对标参考图；如果场景选择会影响方向，先询问一个具体环境范围。没有可用场景参考时，不直接凭文字生成全新背景。
- 做后续配图但没有可用的独立人物参考时，需要先生成或取得 `model.png`；封面不能替代人物参考。
- 修改图片但没有目标原图时，先索取目标图片。

## 参考图职责

每张参考图都要在方案和最终提示词中明确用途：

- 人物参考按 [model-reference.md](references/model-reference.md) 单独准备，不与商品图混用。
- 封面通常使用 `model.png`、商品图和场景参考图；商品图只负责商品，人物参考只负责身份，场景图只负责环境和地点结构。
- 后续配图通常使用 `model.png`、商品图和按本张用途分配的场景参考图；封面只在确实需要延续服装或环境时作为额外参考，并明确它不负责人物身份、表情或脸部朝向。
- 修改图片必须使用目标原图；商品图、封面或其他参考图只在确实影响修改时加入。

不要只在文字里提到参考图却不把它交给图片工具。脚本支持多张参考图，传图顺序必须与提示词编号一致。

## 共同交付规则

- 用户只要提示词时，交付完整提示词，不调用图片工具。
- 用户要求直接出图时，先完成方案和提示词，再调用 BananaRouter 脚本。密钥可在 Skill 根目录的本地 `config.local.json` 中配置，具体见 [生图工具配置](references/image-tool.md#配置)；直接由脚本读取，不需要在对话中提供密钥。缺少可用密钥时保留提示词并说明缺失配置，不改用其他模型。
- 用户要求先看方案或确认后生成时，先停在方案和提示词，不提前出图；确认后沿用已确认内容，只修改用户反馈的部分。
- 生成或修改失败时如实说明原因，保留完整提示词，不假称已生成，不创建虚假的图片路径。

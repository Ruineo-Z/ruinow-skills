# 小红书商品分享笔记

帮助经营者围绕商品创作有内容价值的小红书笔记，并由商品链接承接转化。笔记可以分享搭配灵感、场景建议、使用方式或选择思路；不默认写成直接推销。支持不同商品品类，不把某一品类的呈现方法套给其他商品。

## 默认创作顺序

确认读者与内容主题 → 理解商品特点和素材依据 → 确定本篇整体审美与表达方向 → 设计商品如何自然融入穿搭或使用场景 → 规划图片、人物状态和环境关系 → 生成封面与后续配图 → 根据实际画面创作文案。

按用户当前请求推进，不强制从头开始：

- 开始整篇笔记或新封面时，按 [创作准备与笔记方向](references/note-direction.md) 确定读者、内容价值和审美方向；已有明确方向时直接沿用。
- 先按商品特点确定本篇想呈现的整体风格，再安排服装或使用环境、人物、动作和画面。不要先选好人物和场景，再把商品硬加进去。
- 参考图片、人物参考和场景参考按实际任务需要使用；缺少参考不自动阻断创作。需要保持商品外观、人物身份或具体地点时，再选用对应参考。
- 早期确定的是内容重点，不是提前锁定标题或正文。配图应支持内容重点；成图后核对实际画面，再展开文案。
- 用户已有图片、只需写文案时，按现有素材处理；局部修改沿用已确认方向，不强制重走整篇流程。
- 标题候选、正文和话题标签可以一起讨论；用户只改一部分时，仅处理该部分，除非相关内容确实不一致。
- 不自动发布笔记、挂商品、查询经营数据或安装到全局目录。用户主动给出数据时按 [数据诊断](references/data-diagnosis.md) 定位问题环节。

## 商品与内容边界

- 商品图片和用户资料提供商品依据。根据品类读取可见特征、结构、规格和实际用途；生成图不能证明商品性能。
- 不凭图片确定材质成分、尺寸、价格、性能或顾客反馈。用户没有提供的客观商品事实不写成已核实信息；没有依据且不影响本篇方向的内容省略。
- 分享口吻可以按用户要求创作，不要求证明用户本人真实经历过；不要把虚构经历、评价或数据包装成已经核实的顾客反馈或客观事实。
- 商品词是否进入标题和正文由本篇主题判断，不把直接推销或刻意隐藏商品关系设为默认。内容应先兑现标题承诺，再自然说明商品与主题的关系；商品链接由发布者按平台功能添加。
- 不承诺曝光、流量、排名或成交，不把“暗限流”或算法传言当作已确认事实。

## 图片设计原则

- 先定本篇整体审美与商品适配，再推导服装或使用场景、人物状态、环境互动、光线和构图。审美词需要落实为可见的颜色、形状、材质、空间和明暗关系。
- 商品展示要服务整体造型或使用情境。检查商品和人物、服装、环境是否协调好看，而不只检查商品是否露出。
- 人物可以是有设计的拍摄状态，不必伪装成随手抓拍；动作、表情和视线要与当下情境相容，商品也要符合实际使用和受力关系。
- 环境同时考虑长期使用留下的痕迹和拍摄当下正在发生的活动。只选与地点和内容相符的细节，不把杂物当作真实感装饰。
- 景深和模糊应符合相机、焦点、拍摄距离及前后空间关系。人物对焦时，其他区域随距离自然变化；不添加缺少镜头原因的局部模糊。
- 光线按现场条件推导。每张图不必套用同一光线、景深、姿势或风格。
- 生成前核对方案；生成后直接交付由用户判断，不自动审核、重试或把“真实感”简化成增加毛孔、噪点和瑕疵。

## 交付规则

- 用户只要提示词时，交付完整提示词，不调用图片工具。
- 用户要求直接出图时，先完成设计和提示词，再调用 BananaRouter 脚本。密钥从 Skill 根目录本地配置读取；缺少配置时保留提示词并说明，不擅自改用其他模型。
- 用户要求先确认方案时，停在方案和提示词；确认后沿用已确认内容，只改反馈涉及部分。
- 生成或修改失败时如实说明，保留提示词，不假称生成成功或创建虚假图片路径。

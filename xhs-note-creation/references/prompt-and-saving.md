# 提示词与保存

## 生成提示词的组织方式

人物参考、封面和后续配图可使用结构化 JSON 组织提示词。JSON 是交给图片模型的文本，不是 API 请求体；本地 Agent 将它和实际需要的参考图传给 [生图脚本](image-tool.md)。不需要为每个简单图片任务强行填写所有字段。

```json
{
  "type": "图片类型",
  "goal": "图片用途、内容价值和整体审美方向",
  "references": [
    {
      "id": "REFERENCE_0",
      "source": "商品图路径或标识",
      "role": "提供本次需要保持的商品外观、结构或使用状态"
    }
  ],
  "subject": {
    "person": "需要时描述人物身份；没有身份参考需求时省略",
    "outfit_or_use": "商品与服装搭配，或商品在场景中的使用关系",
    "pose_or_action": "本张人物或使用者的状态和动作"
  },
  "scene": {
    "background": "环境、长期使用痕迹及当下活动",
    "lighting": "现场光源和明暗关系"
  },
  "composition": {
    "camera": "设备与拍摄者位置",
    "framing": "主体位置、大小、留白和景别",
    "focus_and_depth": "焦点及符合距离关系的清晰变化",
    "visual_focus": "第一视觉重点",
    "aspect_ratio": "3:4"
  },
  "style": {
    "finish": "整体画面观感",
    "color_and_retouching": "颜色、曝光和修饰方式"
  },
  "constraints": {
    "must_keep": [],
    "avoid": []
  }
}
```

只保留影响结果的字段和决定。商品图、人物图和场景图按任务决定是否使用，并逐一说明其用途；没有参考图时不虚构引用。

## 参考图映射

参考图按实际输入顺序编号，并在提示词中逐一说明。人物、商品、场景或风格参考都只承担本次指定的职责；如需继承参考图中的其他部分，应明确写出。

- 人物身份需延续时，人物图负责需要保持的身份特征，不自动锁定表情、服装和构图。
- 商品图按商品品类说明要保持的外观、结构、尺度或可见使用方式；不需要的背景和人物信息不自动继承。
- 场景图用于复现具体地点或空间关系时，说明要保留的地点特征；不需要时无需索取。
- 修改图片时，目标原图作为主要参考；其他参考只在确实影响修改时加入。

## 提示词表达要求

- 先写图片用途和整体审美，再写商品与服装或使用情境的关系，以及人物、环境、镜头和质感。
- 每个决定只表达一次，不在多个字段中重复或互相冲突。
- 描述图中可见的状态，不写与成片无关的故事和不可见信息。
- 抽象感受要由可见的搭配、颜色、空间、动作和光线关系支撑。
- 虚化需要对应焦点、设备和空间距离，避免缺少镜头原因的区域性模糊。
- 不通过堆叠“真实”“自然”“高级”等形容词或负面约束代替画面推导。
- 用户要求文字时再添加排版字段；默认比例为 3:4，用户指定其他比例时遵从要求。

## 保存目录

每篇笔记使用独立目录：

```text
<工作目录>/
└── YYYY-MM-DD-笔记名称/
    ├── cover.png
    ├── cover.md
    ├── 1.png
    ├── 1.md
    └── note.md
```

- 目录名包含创作日期和笔记名称；一个目录只保存一篇笔记。
- 图片和提示词使用相同主文件名；格式按实际保存结果，不只改扩展名。
- 修改版本用 `cover-v2`、`1-v2` 等名称，保留旧文件。
- 文案按 [文案交付与保存](copy-and-saving.md) 保存到同一目录。

## Markdown 记录

每张图片对应一份 Markdown 记录，保存最终提示词、实际使用的参考图及其用途、生成状态和图片路径。仅提供提示词或等待确认时也保留记录，并明确状态；生成失败时不填虚假的图片路径。

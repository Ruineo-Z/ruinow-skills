# 正文创作与修改

## 职责

承接标题和图片，先兑现读者期待的灵感、建议或信息。商品与主题相关时自然融入；不要求每篇都介绍商品或把商品写成问题的解决方案。商品链接由笔记的商品区域承接，正文默认不写“点链接”或催单话术。

## 结构：开场 + 展开

正文分两段职责。句数不预先设定，由这一篇要完成的职责决定；相邻职责可以合并进同一句。内容从 [创作准备](note-direction.md) 确认的目标读者和可见事实清单里取。

### 开场（必备，放在最前）

用正文开头的一小段接住目标读者的内容兴趣：说明场景、问题、风格期待或想看的结果，以及这篇会提供什么。标题没有直接出现商品名时，只有在读者理解主题确实需要时，才在开头交代商品与主题的关系。

- 取自确认过的 [目标人群](note-direction.md#目标人群)，不临时另编人群。
- 不写与读者无关的铺垫或碎碎念，也不是机械重复标题的词语。

### 展开（按素材选）

按本篇主题从 [可见事实清单](note-direction.md#可见事实清单) 里取内容。商品信息不是必写项，只有确实有助于兑现标题承诺时才写：

| 职责 | 读者获得 | 是否必备 | 什么时候需要 |
|---|---|---|---|
| 商品可见事实 | 这是什么、长什么样 | 按需 | 商品本身是主题重点，或有助于理解内容时 |
| 搭配或用法 | 我能怎么搭配或使用 | 按需 | 主题涉及搭配或用法，且素材能支持时 |
| 画面收束 | 留下一个具体印象 | 可选 | 有好的画面瞬间时 |
| 对比选择 | 如何在选项中判断 | 可选 | 有可比较的对象时 |
| 互动引导 | 有想聊的话 | 可选 | 读者处境本身容易引发讨论时 |

## 从读者处境推理

开场之后不要急着逐项介绍商品。先从目标读者的处境推理：她什么时候用到、在什么天气、在做什么、担心什么，再落到商品。这样场景具体，读起来像了解这件事的人在说话，而不是商品介绍。

- 可按用户要求采用第一人称分享口吻或创作情境；不要求证明表达者亲历过该场景。但不能把虚构内容包装成已核实的顾客反馈、商品检测结果或经营数据。
- 商品性能、材质、尺寸、价格、顾客反馈只能从用户提供的资料里取，没有就不写。
- 句子长短可以不一样，允许短句和口语词（挺、其实、就），不要每句都完整、等长。
- 用具体搭配解释支撑喜欢，而不是连续形容“高级”“百搭”“绝绝子”。审美偏好可以表达，适用范围不要无依据扩大成“任何人都适合”。

## 商品如何进入正文

商品资料可以帮助具体呈现搭配、用法或选择，但不必每次都转译成卖点。先确认正文自身要给读者什么，再判断商品信息是否相关；无关时可以少写或不写。

不要为了商品出场而从穿搭里的偶然细节制造问题。例如，不能只因为画面里有黑裙，就写成“黑色穿搭显空”，再让披肩充当解决方案。若要说明搭配效果，应当是整体造型确实呈现出的结果，而非给商品找理由。

当商品确实是内容的一部分时，可按下面的关系说明，不必每篇走完所有步骤：

```
商品特点 / 功能  →  使用场景  →  可理解的结果  →  读者能获得什么
```

对照看差别：

- 停在参数：`70% 羊毛，200 克克重` —— 读者无感。
- 转译之后：结合用户提供的性能资料和内容情境，说明它在什么场景中如何被搭配或使用。

场景可以帮助读者理解一套搭配或一种用法，但不应成为硬套商品的借口。只有确有帮助时，才说明商品特点或场景结果。

商品信息的依据边界：

- **看得见的**（颜色、形状、搭配效果、使用状态）→ 需要时用文字和图片一起说。
- **看不见的**（性能、舒适度、耐用性）→ 只有用户提供的资料或明确允许的创作情境支持时再写，不能作为图片已证明的事实。
- **与本篇无关或图片、资料都支持不了的** → 不写，不为完整而补充。

## 具体与自然

- **硬句**：带实体信息的句子，如颜色、版型、纹路、领口、下摆、怎么穿、配什么。
- **软句**：负责语气和画面的句子。
- 具体信息和自然表达都服务于主题，不要求每句都介绍衣物或商品。需要表达审美判断时，尽量落到实际搭配、颜色关系、穿着状态或画面上；不必把每个感受都包装成商品卖点。
  - `好看` → `奶白色配深蓝长裙，站在金黄草原里很显眼`
- `舒服` → `风把流苏和裙摆一起吹起来`

## 长度

默认约 100 字起，素材多时可以到 150 字左右。以职责完成为准，不卡字数，也不为了凑字数写满。

分段和换行方便手机阅读。正文可以少量用 emoji，通常一篇 0～2 个，放在确实有语气或段落提示作用的位置；不连续堆叠，也不用 emoji 替代具体信息。

## 互动设计

读者点进来之后，收藏和评论是两种不同的动作：**收藏是“以后要用”，评论是“现在想说”**。只让人收藏，说明有用但没什么可聊的；只让人评论，说明热闹但没留下价值。

想要评论，结尾要给一个真正有讨论空间的问题，而不是能一个字回答的问题：

- `这个好看吗` —— 可以只回“好看”，等于没问。
- `你们秋天最怕哪种天气` —— 人人有话说。

问题要和正文讲的事情接得上，不为引互动硬加一句。也不要用“记得收藏”“你学会了吗”这类客服腔，那是催人办事，不是聊天。

## 去味检查

初稿写完后对照下面这份清单检查，让文字像人在说话。清单是检查线索，不是词语黑名单。

- **不为改而改**：没有问题的句子不改。
- **分享情境可创作，客观事实不可冒充**：可以按用户要求设计分享场景和第一人称表达，但不伪造商品数据、顾客评价或可核实的经营结果。
- 每处命中都回到上下文判断：是否空泛、重复、不像人说话。

要检查的模式：

- **假对比**：`不是X，而是Y` 只用于抬高语气时删掉。
- **伪深度金句**：拟人化、对仗的句子，如“白和深蓝都安静”。
- **句尾拔高**：只重复赞美的尾巴，如“，太出片了”。
- **三连形容词 / 四字排比**：如“温柔百搭、显瘦显高”。
- **名词参数罗列**：像商品参数表一样堆名词，不是人在说话。
- **模板话术**：`直接抄`、`闭眼入`、`谁懂啊`、`被问爆`、`姐妹们冲`。
- **句式整齐**：连续句子同结构、同长度；真人说话不会这么齐。
- **万能开头**：如“秋天到了，……”这类没有信息的背景铺垫。
- **客服腔收尾**：`你学会了吗`、`记得收藏`。

## 话题标签

完整文案默认给一组精简的话题标签，数量服从主题，不为凑数固定六个。从已确定的主题里选商品、内容、场景、风格或目标人群词。标题采用需求优先型写法时，标签应保留能识别商品关联的词。

- 每个标签都要能回答“读者会在什么情况下同时搜到这一篇”。
- 标签之间围绕同一需求与主题，形成一个关联簇：需求 / 场景、搭配结果、商品或品类之间要能互相解释，避免关联很弱的词，也不把无关热门标签拼进来。
- 每个标签都要能在图片或文字里找到对应内容。
- 地域只有在与内容确实有关时使用。
- 没有足够的标签就少给，不为凑数添加。
- 标签不能单独承诺标题没有依据的效果，也不能用泛生活标签掩盖商品与主题的脱节。

标签用 `#话题` 形式，按 [文案交付规则](copy-and-saving.md) 放在独立代码块中。仅请求正文时不自动附标签；仅请求标签时依据已有内容选择，不重写标题正文。

## 与标题、图片和标签一起检查

- 标题提出的问题、效果或数量，是否在正文和配图里得到支持？
- 标题、正文开头、配图和标签是否在讲同一件事？
- 如果标题没有直接写商品名，正文是否在读者需要理解时自然交代商品与主题的关系？不要仅为露出商品而重复介绍。
- 开场有没有让读者判断与自己的关系？
- 商品特征、搭配或用法、场景和图序是否和画面相符？
- 标签是否与内容相符、彼此关联？

收到反馈时沿用已确认的方向、图片和有效文字，只调整有关部分。用户修改主方向时，检查标题、正文和标签是否需一起变动，不无理由重做图片。

讨论稿和最终稿按 [文案交付规则](copy-and-saving.md) 输出。
